# Environment Variables Configuration

This file documents all environment variables used in CoinGameDz.

## Frontend Variables

Create a `.env.local` file in the project root:

```
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=
```

### Variable Details

| Variable | Source | Purpose | Public? |
|----------|--------|---------|----------|
| `VITE_SUPABASE_URL` | Supabase Dashboard → Settings → API | Supabase project URL | ✅ Yes |
| `VITE_SUPABASE_ANON_KEY` | Supabase Dashboard → Settings → API | Public API key for frontend | ✅ Yes |

**How to get these values:**
1. Go to [app.supabase.com](https://app.supabase.com)
2. Select your project
3. Click **Settings** → **API** in left sidebar
4. Copy the values from there

## Backend Variables

Create a `.env` file in the project root (do NOT commit this):

```
SUPABASE_URL=
SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
TELEGRAM_BOT_TOKEN=
NODE_ENV=development
PORT=3000
```

### Variable Details

| Variable | Source | Purpose | Public? | Required? |
|----------|--------|---------|----------|-----------|
| `SUPABASE_URL` | Supabase Dashboard → Settings → API | Supabase project URL | ✅ Yes | ✅ Required |
| `SUPABASE_ANON_KEY` | Supabase Dashboard → Settings → API | Public API key | ✅ Yes | ✅ Required |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase Dashboard → Settings → API | **Secret backend key** | ❌ **NEVER** | ✅ Required |
| `TELEGRAM_BOT_TOKEN` | Telegram Bot Father | Token for bot operations | ❌ **NEVER** | ⏳ Optional (Stage 5) |
| `NODE_ENV` | Manual | Environment (development/production) | ✅ Yes | ⏳ Optional |
| `PORT` | Manual | Backend server port | ✅ Yes | ⏳ Optional |

**⚠️ CRITICAL SECURITY NOTES:**

1. **Service Role Key is SECRET** — Only used in backend code, NEVER in frontend
2. **Do NOT commit `.env` file** — Use `.env.example` for documentation only
3. **Do NOT hardcode credentials** — Always use environment variables
4. **Use different keys for each environment** — dev, staging, production
5. **Rotate keys periodically** — For security best practices

## How to Get Credentials

### Supabase Credentials

1. Go to [app.supabase.com](https://app.supabase.com)
2. Select your project
3. Click **Settings** in left sidebar
4. Click **API**
5. Copy:
   - **Project URL** → `SUPABASE_URL`
   - **Anon Public** → `VITE_SUPABASE_ANON_KEY` and `SUPABASE_ANON_KEY`
   - **Service Role Secret** → `SUPABASE_SERVICE_ROLE_KEY` (keep private!)

### Telegram Bot Token

1. Message [@BotFather](https://t.me/botfather) on Telegram
2. Send `/newbot`
3. Follow the prompts
4. Copy the API token
5. Store as `TELEGRAM_BOT_TOKEN`

## Environment Files Structure

```
CoinGameDz/
├── .env.example           ← Template (commit this)
├── .env                   ← Actual values (DON'T commit)
├── .env.local            ← Local overrides (DON'T commit)
├── .env.production       ← Production values (DON'T commit)
├── .gitignore            ← Should include .env*
└── src/
    └── services/
        └── supabaseClient.ts  ← Uses VITE_SUPABASE_* variables
```

```bash
# The app will use VITE_SUPABASE_* from .env.local
```

## Common Issues

| Issue | Cause | Solution |
|-------|-------|----------|
| `VITE_SUPABASE_URL is undefined` | Missing `.env.local` | Create `.env.local` with correct values |
| `Invalid API Key` | Wrong key used | Use Anon Public Key for frontend |
| `Service role key not found` | Backend can't access `.env` | Ensure `.env` exists in project root |
| `RLS policy rejected` | User not authenticated | Implement auth in Stage 5 |
| `Tables don't exist` | Migration not applied | Run migration in Supabase SQL Editor |

## Production Deployment

For production:

1. Create `.env.production` with production Supabase keys
2. Never use development keys in production
3. Enable HTTPS only
4. Enable Supabase database backups
5. Monitor API usage and rate limits
6. Set up alerts for suspicious activity
